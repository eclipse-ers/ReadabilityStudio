Word/Phrase Exclusion List Test Plan

Covers the Words & phrases to exclude feature on the Document Indexing page (Options and Project Properties), its Edit Word/Phrase List dialog, and how projects handle a missing or shared exclusion list. Missing files are handled by an automatic project-folder search with a Yes/No substitution prompt, falling back to a plain warning.

What to watch for

  • The exclusion-list controls (path field, edit button, Include first occurrence) live on the Document Indexing page — a top-level sidebar entry in both the Tools tab’s Options dialog and a project’s own Properties dialog, not nested under a separate “Analysis” category.
  • All three exclusion-list controls are disabled whenever Do not exclude any text is the selected Exclusion method — they only make sense alongside incomplete-sentence exclusion.
  • A missing file is handled automatically: the program searches the project’s own folder tree for a same-named file and, if found, asks a plain Yes/No question; if nothing is found, it just warns and drops the path.
  • Importing a settings file bypasses the file-existence check entirely — a bogus exclusion path from an imported settings file is applied immediately, and is only caught the next time someone clicks OK on the Options dialog.
  • A batch project’s subprojects share the parent’s exclusion list object directly; they do not each reload it independently from disk.

Platforms

Exercise every section on all three desktop platforms. File pickers and the project-folder auto-search in section 4 depend on native filesystem behavior that can differ subtly between platforms (case sensitivity, path separators).

  • Windows
  • macOS
  • Linux

Suggested test fixtures

  • Fixture ASmall exclusion list file. A plain text file, one word or phrase per line, no tab characters (single-column format).
  • Fixture BShort sample document. Should contain the phrases ex nihilo, quantum fluctuations, and particles, plus a second, separate occurrence of the bare word fluctuations — exercises the phrase/overlap and first-occurrence rules directly.
  • Fixture CExclusion list matching Fixture B. Three lines: ex nihilo, quantum fluctuations, particles.
  • Fixture DHand-edited settings.xml with a bogus exclusion path. Export a valid settings file, then hand-edit its ExcludedPhrasesPath value to a nonexistent path — the in-app Export flow itself validates the path, so this can’t be produced through the UI alone (see 4.8).
  • Fixture EBatch project using an exclusion list. A batch project with a valid, populated exclusion list configured.
  • Fixture FBatch project with no exclusion list. A batch project where the exclusion path is left empty.

01Setting up the list

Tools tab › Options › Document Indexing page. Repeat against a project’s own Properties dialog for 1.6.

  • 1.1

    With Exclusion set to “Do not exclude any text”, the Words & phrases to exclude field, its edit button, and Include first occurrence are all disabled (grayed out, not hidden).

  • 1.2

    Switching Exclusion to “Exclude all incomplete sentences” or “…except headings” immediately re-enables all three controls, with no need to reopen the dialog.

  • 1.3

    Typing or pasting a path directly into the field is accepted as-is; nothing is validated until OK is clicked (see 4.1).

  • 1.4

    Clicking the edit (pencil) button opens the Edit Word/Phrase List dialog, pre-loaded with whatever path currently sits in the field.

  • 1.5

    Include first occurrence can be toggled even while the path field is empty — it simply has no effect until a list is actually loaded.

  • 1.6

    The same page and the same enable/disable rules from 1.1–1.2 appear identically whether opened from the app-level Options dialog or from a single project’s Properties dialog.

02Edit Word/Phrase List dialog

Open via the edit button next to the exclusion path field. Use Fixture A unless noted.

  • 2.1

    Typing the path to Fixture A into File containing list loads each line as a row under a single column labeled Word/Phrase — no Suggestion/Type/Exception columns for a plain, tab-free list.

  • 2.2

    Clicking the Browse button next to the file field opens a picker filtered to Text files (*.txt); selecting a file behaves the same as typing its path.

  • 2.3

    The Add, Edit, and Delete toolbar buttons above the grid act on the current selection: Add inserts a new row already in edit mode; Delete removes the selected row(s); double-clicking a row edits it in place.

  • 2.4

    Keyboard shortcuts work independently of the toolbar buttons: Del removes the selected row(s), Ins edits the focused row, and Ctrl+Ins adds a new row.

  • 2.5

    Clicking OK with unsaved edits writes the list back to its file: entries are sorted and de-duplicated, one per line.

  • 2.6

    Clicking Cancel/Close with unsaved edits prompts “The list have been edited. Do you wish to save your changes?” — Yes saves, No discards, either way the dialog then closes.

  • 2.7

    With no path yet entered in the file field, clicking OK triggers a Save Word List file dialog before anything is written to disk.

  • 2.8

    Changing the file-path field to a different, existing file while the currently-loaded list has unsaved edits prompts to save those edits to the old file first, then loads the new one.

  • 2.9

    Entering a path to a file that doesn’t exist and moving on: no crash, no rows load, and the grid is left showing whatever was there before — nothing is silently created until an explicit save.

03Exclusion during analysis

Create a project from Fixture B and point its exclusion list at Fixture C.

  • 3.1

    Every exact occurrence of a listed word or phrase is removed from word/sentence/syllable counts and highlighted reports, while the rest of the sentence containing it is still analyzed normally.

  • 3.2

    Matching is case-insensitive: the lowercase list entry quantum fluctuations still matches the capitalized Quantum Fluctuations at the start of the fixture document.

  • 3.3

    Overlap rule: the first occurrence of fluctuations (inside Quantum Fluctuations) is excluded as part of the longer phrase, but the later, standalone occurrence of fluctuations is not excluded, since it isn’t part of a listed phrase.key case

  • 3.4

    With Include first occurrence checked, the very first matching instance of a listed phrase is left in the analysis and only subsequent occurrences of that same phrase are excluded.

  • 3.5

    Highlighted Reports mark excluded phrases the same way other excluded text is marked (consistent with the excluded-text highlighting used for incomplete sentences elsewhere in the program).

  • 3.6

    A list entry that never appears anywhere in the document has no visible effect: no error, no highlighting, the project analyzes normally.

04Missing or invalid file handling

  • 4.1

    In Options (or Project Properties), type a path to a nonexistent file into Words & phrases to exclude and click OK: blocked with “"<path>": excluded phrase file not found.”, and the dialog jumps back to the Document Indexing page instead of closing.key case

  • 4.2

    From that same blocked state, click Cancel instead: the dialog closes and the bogus path is discarded, not written to settings.

  • 4.3

    Create a new project while the app’s default exclusion path is valid: the new project loads with that path already applied and no prompts.

  • 4.4

    Move the referenced exclusion file so a project that points at it can no longer find it at the old path, but leave a same-named copy elsewhere under that project’s own folder tree. Reopen the project: it reports that the file “could not be located” but a same-named file was found at the new location, and asks “Do you wish to use this file instead?” Clicking Yes uses it and marks the project modified.key case

  • 4.5

    Repeat 4.4 and click No: the found file is not used, and the project instead falls through to the plain not-found warning in 4.6.

  • 4.6

    With no same-named file anywhere under the project’s folder tree, reopening the project instead shows an informational “Exclusion phrase list not found… List will not be included in this project.” message (OK only, no Yes/No), and the project’s exclusion path is silently cleared.

  • 4.7

    Check “Remember my answer” on the 4.4 prompt: opening another project with the same kind of missing-but-findable file no longer prompts, and silently applies whatever was chosen the first time. This preference is shared program-wide, not specific to exclusion lists.

  • 4.8

    Use Tools › Options › General Settings › Import… with Fixture D (a settings file whose exclusion path doesn’t exist): the dialog shows “Settings from the selected file will now be applied” and closes immediately — there is no file-existence check at all during import.key case

  • 4.9

    Reopen Options after 4.8: the bogus path from the imported file now shows on the Document Indexing page. Clicking OK blocks per 4.1, but clicking Cancel leaves the bogus path in effect anyway, since Import already wrote it to the app’s settings before the dialog was reopened.

05Batch projects & subprojects

  • 5.1

    Open Fixture E and create a subproject from one of its rows: the subproject uses the exact same exclusion list as its parent batch, not a separate copy reloaded from disk.

  • 5.2

    Open Fixture F (no exclusion list) and create a subproject: it likewise analyzes with no exclusion list and shows no missing-file warning.

  • 5.3

    Change the exclusion list path in Fixture E’s own Properties dialog and reanalyze: existing subprojects reflect the new list, since they share the same in-memory list object as their parent (per 5.1).

  • 5.4

    Save and reopen Fixture E: the exclusion path round-trips correctly and subprojects still share it after reload.

06Persistence & settings

  • 6.1

    A brand-new project (Standard or Batch) inherits its initial exclusion path and Include first occurrence setting from the app’s current Options, not a separate fixed default.

  • 6.2

    Changing the exclusion list only in a single project’s Properties dialog (not the app-level Options) does not change the app-level default used by the next new project.

  • 6.3

    Save a project with a custom exclusion list, close and reopen it: the path and the Include first occurrence setting are restored exactly as saved.

  • 6.4

    With an invalid path currently entered in the open Options dialog, click Export…: this is blocked by the same “file not found” validation as clicking OK (4.1) — Export cannot produce a settings file while the open dialog itself has a flagged-bad path.key case
