What to watch for

  • This is a sidebar-book wizard, not a classic linear wizard: every sidebar entry is directly clickable, so a tester can jump straight to Preview without ever visiting Document Structure or Test Selection.
  • Composition (narrative vs. non-narrative/fragmented) and Layout (three independent checkboxes) are two separate groups on the Document Structure page — they are not one big radio set.
  • All validation happens at Finish, not when moving between pages.
  • Document Structure choices are not saved as new defaults when the wizard finishes — they only seed from whatever the app’s own paragraph-parsing preferences already were.
  • For Test Selection, only the method actually active at Finish (document type, industry, manual, or bundle) has its settings remembered for next time.
  • The Preview page renders against a private scratch project; nothing done there can affect the real project being created.

Platforms

Exercise every section on all three desktop platforms. File/folder pickers, the recursive directory scan, and the Preview page’s embedded web view are all backed by different native components per platform.

Suggested test fixtures

  • Doc ASmall English narrative file. A plain paragraph-and-sentence document for quick baseline runs.
  • Folder BMixed batch folder. A folder (with at least one subfolder) containing several document types, for Add folder’s recursive toggle and file-type filtering.
  • Archive CSmall zip of a few documents. For Add archive; include a password-protected archive as a negative case if one is on hand.
  • Workbook DMulti-sheet .xlsx or .ods file. At least two sheets, one with more rows than fit on screen, for the sheet-picker and cell-range preview.
  • Legacy EOld binary .doc file. For the automatic hard-return override on legacy Word documents.
  • Site FSmall crawlable website. A handful of internally-linked pages, for Add web pages.
  • Non-English GSpanish and German samples. For language-filtered test lists and Dolch enable/disable.
  • Long HDocument over ~300 words. For the Preview page’s excerpt-cutoff logic.
  • Short IDocument under ~300 words. Preview should show it in full, with no trailing ellipsis.

01Document entry — Standard project

File › New › Standard Project (or the equivalent ribbon button). Use Doc A unless noted.

  • 1.1

    The language choice offers exactly English, Spanish, German, in that fixed order.

  • 1.2

    Default source is “Read text from a file or webpage”: its file field and Browse button are enabled; “Manually enter text” and its field are disabled.

  • 1.3

    Selecting “Manually enter text” enables its multi-line field and disables the file path field and Browse button; switching back re-enables the file field and disables the text field.

  • 1.4

    Clicking Browse opens a file picker; choosing a file fills in the file path field.

  • 1.5

    Typing a web URL directly into the file path field (no browsing) is accepted as a valid source.

  • 1.6

    With “from file” selected and the path left empty, click Finish: the Browse dialog opens once as a last chance; canceling it jumps to the Document page and shows “Please enter a file to be analyzed before continuing.”

  • 1.7

    Type a path to a file that doesn’t exist and click Finish; after canceling the last-chance Browse dialog, the message becomes “File not found. Please enter a valid file to be analyzed before continuing.”

  • 1.8

    Leave “Manually enter text” completely empty and click Finish — this is allowed; no validation blocks it (only Preview will show “not available”).

02Document entry — Batch project

File › New › Batch Project. Use Folder B, Archive C, Workbook D, and Site F across these cases.

  • 2.1

    All six add-source buttons are present and open distinct dialogs: Add folder…, Add files…, Add archive…, Add spreadsheet…, Add web pages…, Add web page… (the last is the singular, single-URL variant).

  • 2.2

    Add folder exposes a recursive-search toggle; unchecking it excludes files inside subfolders.

  • 2.3

    Add folder and Add files share the same last-used-folder memory: browsing with one, then opening the other, starts in the same folder (see 11.7 for how long this lasts).

  • 2.4

    Any add flow that adds more than one row (folder, files, archive, web pages) prompts for how to label the new rows: use documents’ descriptions, a typed grouping label, or the last common folder between files. The previously-chosen option is pre-selected the next time this prompt appears, including across separate add operations.

  • 2.5

    Choosing a typed grouping label applies that exact text to every row just added.

  • 2.6

    Choosing last common folder between files derives each label by comparing adjacent (sorted) files and using the longest shared folder path between neighbors — verify with files at different folder depths.

  • 2.7

    Add spreadsheet (Workbook D): if it has 2+ sheets, prompts to pick which sheet(s); each chosen sheet then opens a preview for selecting a cell range before import. Only the typed-label grouping option is offered here (no descriptions/last-common-folder choices, since spreadsheet cells don’t have those).

  • 2.8

    Add archive (Archive C): opens an archive browser, then the same grouping prompt as folder/files; extracted entries appear as archive-relative pseudo-paths in the list.

  • 2.8a

    A password-protected archive is rejected with a clear error rather than silently producing an empty or partial list.

  • 2.9

    Add web pages (Site F): crawls the site for links, with the option to download the pages locally vs. keep them as remote URLs.

  • 2.10

    Add web page (singular): typing text that isn’t a resolvable URL is rejected with a warning; a valid URL is appended as one row via the grouping prompt.

  • 2.11

    The small Add / Delete / Group icon buttons above the file list work on the current selection (Add inserts a blank editable row; Delete removes selected rows; Group prompts for a label). Ctrl+G triggers Group from anywhere on this page.

  • 2.12

    Minimum document word count accepts any positive integer; set it high and confirm shorter documents are excluded from the batch at Finish.

  • 2.13

    Checking “% of documents to randomly sample” enables its percentage spinner (1–100); leaving it unchecked leaves the spinner disabled.

  • 2.14

    Click Finish with an empty file list: Add Folder opens once as a last chance; canceling shows “Please select files to be analyzed before continuing.”

03Document Structure

This page is identical for Standard and Batch. Two groups: Composition (Narrative text / Non-narrative, fragmented text — mutually exclusive) and Layout (three independent checkboxes: split sentences, centered/left-aligned text, hard returns start new paragraphs).

  • 3.1

    Narrative text and Non-narrative, fragmented text are mutually exclusive — selecting one deselects the other.

  • 3.2

    The three Layout checkboxes are independent of each other and of Composition — any combination can be checked in the UI itself (blocking only happens at Finish, see 3.7–3.8).

  • 3.3

    Each of the six options has a thumbnail image; clicking any thumbnail (whose source image is larger than the thumbnail itself) opens it enlarged in a modal window, closable by clicking anywhere on it or pressing any key. The split-sentences and hard-returns options each show two thumbnails (before/after) — confirm both render distinctly and both enlarge correctly.

  • 3.3a

    The enlarged image is scaled to fit within the screen’s dimensions — on every monitor in a multi-monitor setup, and at various display scaling percentages, confirm it never extends beyond the visible screen bounds in either direction.

  • 3.3b

    Any text/labels baked into the thumbnail’s source image (e.g., callouts in the before/after illustrations) remain fully legible at the enlarged size — not clipped, blurry, or overlapping the border or the “Click to close” hint in the corner.regression

  • 3.4

    All three “More info…” icon buttons (fragmented text, split sentences, centered text) open the same help topic — not option-specific pages.

  • 3.5

    Check both Centered/left-aligned text and Line ends mark the start of a new paragraph, then click Finish: blocked, returned to this page, with a message to unselect one.key case

  • 3.6

    Check both Sentences are split… and Line ends mark the start of a new paragraph, then click Finish: the analogous blocking message appears.key case

  • 3.7

    On Test Selection, choose document type “Non-narrative form…” while Composition is still Narrative, then Finish: Composition is auto-flipped to fragmented text, with an explanatory info message first.key case

  • 3.8

    Conversely, select Non-narrative, fragmented text on this page while a different document type is chosen on Test Selection, then Finish: the document type is auto-switched to Non-narrative form, with its own explanatory message.key case

  • 3.9

    Finish a project with non-default Document Structure choices (e.g., fragmented text, or centered text checked), then reopen the wizard: this page resets to its ordinary defaults, not to what was chosen last run — Document Structure selections are not saved as new wizard defaults.key case

  • 3.10

    With the app’s own paragraph-parsing preference set so that every new line already starts a new paragraph, and indentation is already being ignored, open the wizard and check whether Centered/left-aligned text opens checked or unchecked. Note whichever it is — the two places in the code that seed this default disagree on whether the line-per-paragraph setting should suppress it.

  • 3.11

    Analyze Legacy E (an old binary .doc file) without checking any Layout box: the resulting project treats every line as a new paragraph automatically. Explicitly checking split-sentences, centered-text, or hard-returns yourself overrides this automatic behavior.

04Test Selection — document type & industry

  • 4.1

    “Choose how to select tests” offers exactly four mutually exclusive options (document type, industry, manual, bundle); switching swaps the panel below it — only one panel is visible at a time.

  • 4.2

    Document type offers 5 choices: General document, Technical document or form, Non-narrative form (fragmented text), Literature, Children’s literature. Selecting each and finishing includes the tests mapped to that classification for the current language.

  • 4.3

    Industry offers 7 choices: Children’s publishing, Young adult/adult publishing, Children’s healthcare, Adult healthcare, Military and government, Second Language (ESL) Education, Broadcasting. Spot-check known mappings, e.g. Broadcasting (English) includes only ELF; ESL (English) includes EFLAW and Dolch; ESL (Spanish) includes only FRASE.key case

  • 4.4

    Selecting a document type or industry with zero tests for the current language shows a non-blocking note (“no tests associated with this … for the selected language”) but still creates the project.

  • 4.5

    Selecting Children’s literature, Children’s publishing, or ESL Education auto-includes Dolch Sight Words for English, even though the Dolch checkbox itself lives on the Manual Selection panel and was never visited.

  • 4.6

    Finish with document type (or industry) selected, then reopen the wizard: that method and its chosen option are remembered.

05Test Selection — manual, custom tests & Dolch

  • 5.1

    The manual-selection list shows only tests supporting the currently selected language; switching language while on this panel live-filters the list.

  • 5.2

    Tests checked before a language switch remain checked after switching, provided they support the new language too; switching back doesn’t lose the original selections for tests that disappeared and reappeared.

  • 5.3

    The Dolch checkbox is enabled only for English; note whether it stays checked-but-disabled or gets cleared when switching away from English, and whether switching back to English restores its prior state.

  • 5.4

    With zero custom tests defined in the app, the Custom Tests list and its column header are simply absent (not shown empty). Add at least one custom test and reopen the wizard to confirm the list then appears alongside the standard tests.

  • 5.5

    Custom tests checked in a previous run are pre-checked again next time, but only if Manual Selection was the method actually used to Finish last time (see 11.3).

  • 5.6

    Ctrl/Shift-click multi-selection works normally in both the standard-tests and custom-tests lists.

06Test Selection — bundles

  • 6.1

    The bundle list reflects whatever test bundles are currently defined; with none defined, the radio box still renders sensibly with an empty option set (no crash).

  • 6.2

    Selecting a bundle and finishing includes exactly that bundle’s tests, regardless of what’s checked on the (now-hidden) Manual Selection panel.

  • 6.3

    Finish with a bundle selected, then reopen the wizard: Test Bundle method and that same bundle are pre-selected again.

07Preview page

Configure Document and Document Structure first, then visit Preview. Use Long H and Short I for the excerpt cases.

  • 7.1

    Preview initially shows only excluded-text highlighting (no readability/Dolch/grammar highlighting), with an “Excluded text” legend banner.

  • 7.2

    Long H (over ~300 words) is truncated, extended out to the end of the sentence containing word #300, with a trailing ellipsis. Short I (under ~300 words) shows in full, with no ellipsis.

  • 7.3

    Editing the file path or manually-entered text and returning to Preview does a full re-extraction and re-render.

  • 7.4

    Toggling a Document Structure option and returning to Preview re-renders from the cached sample without re-reading the source — should be fast, with no flash of “not available.”

  • 7.5

    For a batch project, Preview always reflects whichever file is currently first in the list; reordering or deleting rows so a different file becomes first, then returning to Preview, picks that file up.

  • 7.6

    With an empty batch file list, or a Standard project with neither a valid file nor entered text, Preview shows “Preview not available.”

  • 7.7

    Point “from file” at an unreachable URL or a source that fails extraction: Preview shows “Preview not available for this source.” rather than crashing the wizard.

  • 7.8

    Preview correctly resolves the pseudo-paths produced by Add archive and Add spreadsheet (an archive-internal file; a specific worksheet cell range) — the right extracted text shows, not an error.

  • 7.9

    Preview follows the app’s light/dark mode and the currently selected report theme’s excluded-text highlight color/method.

  • 7.10

    Nothing done on the Preview page (toggling structure options, navigating away and back) alters the real project once Finish is clicked — it renders against a disconnected scratch project.key case

08Navigation & Finish

  • 8.1

    Back is disabled on the first page; Forward is disabled on the last page (Preview); both are enabled on the two middle pages.

  • 8.2

    Clicking a sidebar entry directly jumps straight to that page — including jumping straight to Preview from the first page — with no intermediate validation blocking it.

  • 8.3

    No cross-page validation blocks Forward navigation; every check in this plan that blocks progress happens only at Finish.

  • 8.4

    Cancel closes the wizard without creating a project and without saving any choice made during that run.

  • 8.5

    Help opens the same “Creating a New Project” topic regardless of which wizard page is showing (not context-sensitive per page).

  • 8.6

    F1 (or the platform’s context-help gesture) opens the same help topic as the Help button.

  • 8.7

    The Finish button is labeled “Finish,” not “OK.”

09Language

  • 9.1

    English, Spanish, German are offered in that fixed order, for both Standard and Batch projects, with no restriction on which can be selected.

10New Project from Clipboard

A separate menu command (Ctrl+V / “New Project from Clipboard”), not the wizard dialog itself, but it shares the same project-creation path and can bypass the wizard entirely depending on clipboard content.

  • 10.1

    Copy ordinary prose (not a file path or URL) to the clipboard, then use New Project from Clipboard: the wizard opens with “Manually enter text” selected and that text already filled in.

  • 10.2

    Copy a valid web URL as text (e.g. from a browser’s address bar) and use New Project from Clipboard: the project is created immediately, sourced directly from that URL — the wizard is suppressed.

  • 10.3

    Copy a valid local or network file path as plain text and use New Project from Clipboard: same immediate-creation, no-wizard behavior as 10.2 — only the resolved validity of the string matters, not which clipboard format carried it.

  • 10.4

    Copy one or more actual files (selected in a file manager) and use New Project from Clipboard: a separate new project is created per file, wizard suppressed for all of them.

  • 10.5

    With nothing on the clipboard, or content that is neither recognized text nor files, New Project from Clipboard shows “No text is currently on the clipboard.”

  • 10.6

    Selecting an entry from the Examples menu (Documentation ribbon tab) opens the wizard with that example’s file path already filled in on the Document page — a deliberate exception where the wizard is not bypassed even though a valid file path is involved.key case

11Persistence & regression edge cases

  • 11.1

    Configure Document Structure with non-default choices and finish a project, then reopen the wizard: Document Structure resets to whatever the app’s own paragraph-parsing preferences already are, not to what was picked last run (duplicate of 3.9, retest independently for batch).key case

  • 11.2

    Finish once via document type. Reopen, switch through industry and manual selection (making different choices on each) without finishing, then Cancel. Reopen again: only the original document-type selection from the earlier successful Finish is remembered — none of the cancelled run’s in-between changes persist.

  • 11.3

    In one run, configure Manual Selection with specific tests, then switch to Test Bundle and Finish with a bundle chosen. Reopen: Test Bundle method and that bundle are remembered; the manual test checkboxes chosen earlier in that same run are not saved — only the method active at Finish is persisted.key case

  • 11.4

    In a batch project, add the same folder or file twice and Finish: duplicate rows are silently collapsed to one entry before the batch is built — confirm the resulting project has no duplicate documents.

  • 11.5

    With Random Sampling checked, confirm the sampling percentage is computed against the deduplicated count from 11.4, not the raw list count including duplicates.

  • 11.6

    Leave Random Sampling explicitly unchecked and Finish; reopen the wizard and confirm it stays off — an explicit “off” is remembered just as reliably as an explicit “on.”

  • 11.7

    Use Add folder to browse into some folder, finish or cancel, then start a new wizard in the same app session and use Add folder again: it reopens in that same folder. Restart the app entirely and repeat: it should not remember that folder anymore — this memory is session-only, unlike the file-type filter and grouping-method choice, which are saved to disk.key case
